# Evidence

Everything AccessFinish claims is backed by a file in this folder. Recorded results are not edited after they are recorded; the one status update (`competition-20261021/post-evaluation-compatibility.json`, pending → verified on 21 Oct) is visible in git history.

| Folder / file | What it is | Backs the claim |
| --- | --- | --- |
| [`agent-runs/`](agent-runs/) | All **54 live agent runs** (24–26 Oct 2026, GitHub Actions, Nemotron 3 Super on Nebius Token Factory): every request's tokens and cost, Nemotron's searches, reasoning, diagnoses and edits, every verifier verdict with its evidence, and the verified patch when there is one. Browse them on the [evidence page](https://sultalfaifi.com/accessfinish/evidence.html). | Phone 27/27 · keyboard 2/10 for agents v4–v5 · 77 false "booked" pages caught · $6.38 |
| [`commit-map.json`](commit-map.json) | Old → new commit IDs after the history was rewritten on 26 Oct to change commit authorship only (trees identical). Traces keep the commit they were recorded with; the evidence page links through this map. | Every run's "agent commit" link resolves |
| [`competition-20261021/`](competition-20261021/) | The earlier **single-shot** trials: three development and five frozen evaluation requests, each with Nemotron's request and response, the proposal, the execution record and its claim, plus the frozen protocol and procedure (`development-3` failed at generation, so it has only its request, response and claim). The operator supplied the diagnosis; each proposal got one try. | "Five frozen Nemotron requests with an operator-supplied diagnosis gave 2/5 full passes" |
| [`clean-execution-20261021/`](clean-execution-20261021/) | A fresh-runner CI replay of those five frozen proposals and the original-source control, with the workflow's artifact digest. | Accept/reject decisions reproduce on a clean machine |
| [`extension-ci-20261023/`](extension-ci-20261023/) | A second fresh CI reproduction (four check jobs on Linux and Windows plus the isolated Linux booking job) including the phone-case controls. | Hard-coded phone patch rejected by a second customer; reference fixes verify |
| [`reproduction-variation-20261024/`](reproduction-variation-20261024/) | The 24 Oct replays where one known-bad proposal was rejected at an earlier stage than originally recorded — reported as 4/5 exact stage matches, not hidden. See its [README](reproduction-variation-20261024/README.md). | "Failure stage 4/5 on 24 Oct" |
| [`phone-model-20261023/`](phone-model-20261023/) | The first Nemotron request on the seeded phone fault (frozen protocol, public pricing at the time, raw request/response, spend and execution), with its [archived procedure](phone-model-20261023/procedure/). | The recorded Nemotron phone proposal that `--recorded-model` replays and CI re-verifies |
| `inference.json`, `model-run.json`, `normalized-*.json`, `independent-outcome.json`, `earlier-failed-run.json` | The first recorded example from 18 Oct, including the two failed requests before it and the independent read-only database and fresh-browser outcome check. They were produced by the early Windows harness, kept in history at [`integration/windows-harness` @ 6d292fa](https://github.com/SultanAlfaifi/accessfinish/tree/6d292fa/integration/windows-harness). | Where the project started |

Checks that re-verify this folder: `npm run check:evidence`, `npm run check:records` and `npm run check:phone-model` (CI runs them on every pull request and every push to the default branch), and `node scripts/evidence-index.cjs`, which rebuilds the evidence page index from `agent-runs/`.
